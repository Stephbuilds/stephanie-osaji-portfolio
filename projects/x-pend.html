X-PEND — Expense Approval Workflow

An internal tool for employees to submit expenses with receipts and for managers to approve or deny them. What makes this case study interesting isn't the first version — it's three rounds of real iteration, each one triggered by a specific piece of feedback rather than a redesign for its own sake.

Node.js Express SQLite Multer (file uploads) Vanilla JS

The problem

Employees need a simple way to submit an expense (amount, reason, date, optional receipt) and have a manager review, approve, or deny it — with enough context (who submitted it, what proof exists) that approval decisions are fast and defensible.

Three iterations, each grounded in feedback

v1 → v2: from a closed roster to open self-service login

The first version used a fixed dropdown of pre-defined employee and manager names — fine for a demo, wrong for a real company. When the requirement came in that "access should be open to everyone, logging in with a company email," I removed the fixed roster entirely and replaced it with self-reported name + email identity, with managers kept separate from employees only by which dashboard they're using — not a hardcoded permission list.

v2 → v3: merging two pages into one product

The employee and manager views started as two separate pages linked by navigation. After direct feedback that this felt like unnecessary browser-tab clutter, I merged both into a single page with an in-app Employee/Manager tab switcher — same functionality, zero page reloads, and actions in one tab (like an approval) now live-refresh the other.

Root-causing a UX bug instead of patching the symptom

The "Submit expense" button appeared disabled with no clear reason why. The surface-level fix would have been tweaking the button's disabled state. The actual root cause was structural: the form was visible before login, so nothing signaled that logging in was the real prerequisite. The fix was gating the entire form behind a login state — the button issue disappeared because the confusing state it was in could no longer occur.

Notable product decisions

Managers can self-approve

Rather than force a separate approver for every submission — unrealistic for a small team — a manager can submit their own expense on the employee side and approve it themselves on the manager side. It's an intentional trust-based design choice for an internal tool, not an oversight.

Receipts: optional, but the UI nudges for one

Requiring a receipt would block legitimate low-friction expenses; omitting the nudge would reduce approval quality. The form marks receipts "optional, but recommended" and the manager view clearly flags "No receipt uploaded" so the tradeoff is visible at decision time, not hidden.
